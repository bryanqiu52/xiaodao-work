新建的待办开始带「看得懂的编号」了：谁建的、归哪一类、第几条，扫一眼就知道。

主要变化

- **新建的待办自动生成可读编号**（如 `cl-001`、`plan-002`）：编号 = 领域前缀 + 3 位序号，
  不再是 `imtvb3v58-mqn9hs` 那种随机串
- **按领域分别排号**：客户业务的第一条是 `cl-001`，发展规划的第一条是 `plan-001`；
  某个领域已经有编号的，新条目接着往下排（`cl-002`、`plan-002`…），不会撞号
- 前缀对照表：

  | 领域 | 前缀 | 例 |
  |:--|:--|:--|
  | 客户业务 | `cl` | `cl-001` |
  | 公司建设 | `co` | `co-001` |
  | 内容创作 | `ct` | `ct-001` |
  | 发展规划 | `plan` | `plan-001` |
  | 小刀升级 | `as` | `as-001` |
  | 个人事务 | `pe` | `pe-001` |

- **编号跟 AI 那边（小刀技能）用的是同一套规则**：桌面端建的和小刀建的不会有两种写法，
  跨对话说"cl-003 那条"时双方指的就是同一条
- 自己加的领域分类（设置 → 待办里改过的那套）仍用随机编号，照常能用、不会被拦

说明

- **已有待办的编号一个都没动**：`imp-…`、`imt…`、`i…` 这些老编号原样保留，
  它们上面的关联（`relates`、产出 `files`）不受影响。新的编号规则**只对以后新建的条目生效**
- 编号扫的是**全部条目**（含已完成、已移出的），所以删掉一条之后号不会被回收再利用，
  历史记录不会跟新条目撞号
- 不想要这个编号规则的话，把领域的**分类名**改成前缀表里没有的（设置 → 待办），新条目就回到随机编号
- 数据在 `%APPDATA%\小刀工作台\`，升级不会动数据
- 安装包没有代码签名，首次运行 Windows 会拦一下，点「更多信息 → 仍要运行」
