# 2026-10 归档

## 2026-10-27 - 跑着跑着任务栏图标又冒出来了

### 现象

设计要求是"只在托盘有图标，任务栏不要"。用了很久都没问题，某天开始任务栏上又出现一个"小刀工作台"。

### 查到的东西

直接读正在运行的那个窗口（`xiaodao_work` PID 39196，主窗口 hwnd 0x1d0c5a）：

```
exStyle = 0x40118  -> APPWINDOW-有任务栏按钮 | TOPMOST
```

`WS_EX_TOOLWINDOW`（0x80）**已经不在了**，换成了 `WS_EX_APPWINDOW`（0x40000）——
所以任务栏按钮就回来了。

Windows 不提供"窗口样式被改了"的通知，代码里也查不出是谁改的（`set_always_on_top` /
`show` / `set_focus` 都改不到这一位），继续猜成本很高。日志里今天没有 `[任务栏] 已从任务栏摘掉`，
说明进程是从前一天一直跑到现在的 —— 样式是在**运行途中**被改回去的，不是启动没设上。

### 方案

与其找凶手，不如盯住结果：新增 `desktop::start_taskbar_guard()`，
起一条后台线程每 2.5 秒检查一次，样式不对就重设（`GetWindowLong` 一次而已，开销可忽略，
没变化的时候不写日志）。`lib.rs` 里启动那三次固定重试（300/700/1200ms）换成它 ——
固定次数挡不住"跑一阵子之后才被改"。

顺带留了抓手：守卫发现不对时会打 `已从任务栏摘掉（exStyle 0x40118 → 0x88）`，
前后两个值都在日志里，下次再出这类事就能知道它是从什么状态被改回去的。

### 结果

`cargo check` 通过。要生效得打包新版本并重启程序。

## 2026-10-26 - 产出文件右键「打开所在文件夹」到不了目标目录

### 现象

产出 chip 右键「打开所在文件夹」后，资源管理器确实弹出来了，但**停在它自己的默认位置**，
既没切到那个文件的目录，也没选中文件。看起来像"开了个文件夹、跟这条待办没关系"。

### 原因

`src-tauri/src/open.rs` 里 `open_folder` 把路径按原样拼给了 explorer：
日志里那一笔是

```
[打开产出] explorer /select,"E:/Digital World/_小刀产出/.../2026-10-14-电商候选-16x9裁切验证.jpg"
```

路径是**正斜杠**。`files` 里这种写法是 AI 写的，很常见；而 Windows 自己的文件 API 认正斜杠，
于是 `p.exists()`、白名单 `canonicalize` 检查一路顺风通过，偏偏 explorer 不认，
收到就当无效参数处理 —— 资源管理器照常启动，只是不导航。

**实测对照**（同一个真实文件，用 `explorer` 实跑后用 Shell COM 读窗口路径，每种形态跑前先把该目录已开的窗口关掉）：

| 参数形态 | 结果 |
| --- | --- |
| `/select,"E:/Digital World/.../xxx.jpg"`（正斜杠，当时的写法） | 目标目录**没打开**，窗口列表里没有它 |
| `/select,"E:\Digital World\...\xxx.jpg"`（反斜杠） | 正常打开并选中该文件 |
| `"E:\...\某目录\"`（目录 + 尾斜杠） | 正常打开该目录（这条不是本次的根因） |

也就是说：**唯一的差别就是正斜杠**，引号那层（代码里早已用 `raw_arg` 处理）不是这次的问题。

### 方案

新增 `explorer_path()`：交给 explorer 前先 `canonicalize`（理正盘符大小写、`..`），
再用 `simplify_path` 剥掉 `\\?\` 前缀，最后把 `/` 统一换成 `\`。
`open_folder` 的 `/select,` 与"直接开目录"两个分支都过这一步。

### 结果

`cargo check` 通过。正斜杠写法不复存在，两种入口（文件选中 / 目录打开）走同一条规范化路径。
待验证：重新打包后在同一条产出上右键，资源管理器应直接落在那个文件所在目录并选中它。
